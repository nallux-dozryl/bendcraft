# Pinned 26.3 campfire cooking authority

`src/campfire_authority.bend` implements the four food slots owned by the actual Java 26.3 campfire block entity. Ordinary and soul campfires share its cooking behavior. The block kind remains part of the owner for the world consumer; their damage, emitted light, smoke and block interaction differences remain block/world responsibilities. Campfires award no cooking XP. Recipe experience fields are loaded and deliberately ignored by this owner.

## Consumer API and ownership

Import `campfire_authority.bend` as `CA`, `campfire_authority_items.bend` as `CI`, and `campfire_authority_loader.bend` as `CL`.

- `CI.Input{slot:Inventory.Slot,patch:Json.Value}` carries the complete item key/count and its actual component patch. `CI.Context{recipes:CookingRecipe.Catalog,defaults:List<CraftingRecipeComponents.Default>,features:Map<Maybe<Bool>>}` binds the loaded recipe book, initialized component defaults and current item feature admission. `CL.catalog(Json.Value)` loads that context from the existing cooking catalogue JSON plus a `campfire_features` array of `{id,enabled}`. `CL.parse(text,max_codepoints,max_depth)` uses caller-selected parser bounds. Neither recipes nor the production item domain are hardcoded.
- `CA.State{kind:Ordinary|Soul,lit:Bool,cells:Four<Cell>,cached_recipe:Maybe<String>}` is affine. Each `Cell{input,progress,total}` preserves the raw Java signed-int timer words in `U32`. Four is the actual product slot count, not a test bound. `CA.new(kind,lit)` creates empty slots and zero timer words.
- `CA.place(context,state,held,infinite)` returns `State & Placement{remaining,status:Result<String,U32>}`. The first empty slot receives exactly one complete item key and patch; progress becomes zero and total snapshots the matching current recipe's cooking time. `infinite` must come from the authoritative player's abilities. Lit status does not gate placement. No matching recipe, full slots or failed admission preserve both the complete campfire owner and held input. `CA.placement_effects(placement)` supplies one dirty notification, one block update and one block-change event for accepted placement, and none for refusal.
- `CA.step(context,state)` returns `State & Result<String,Effects>`. `Effects{drops:List<Drop{slot,item}>,dirty,block_updates,block_changes}` contains ordered complete drop intents. Apply them only after `Done`. Missing current authority or an unsupported campfire recipe domain returns the whole original owner and no effects; a failure in a later slot cannot commit earlier drops or cache changes. Call once per authoritative world tick.
- `CA.set_lit(state,next)` retains items/timers and resets the ephemeral cached recipe ID when lit status changes. `CA.cache_reset(state)` handles ticker replacement for other real block-state changes. A recipe reload changes `Context.recipes`; it preserves the existing cached check until the real ticker is replaced.
- `CA.remove(state)` returns the owner with every item payload cleared plus exactly four ordered drop calls, including empty slots. Empty intents must reach the real drop adapter because Java draws three position random values before its empty check. Timer words and other owner fields remain intact. Repeated removal emits no duplicate items; its four empty intents retain Java's empty-call behavior. Call only after the real Core/world owner accepts block removal. `CA.clear(state)` clears payloads without drops, matching Java `clearContent`.
- `CA.snapshot(state)` returns the same whole affine owner plus `Record{cells}`. `CA.load_record(context,state,record)` validates the entire record before replacing cells and resets the ephemeral recipe cache; refusal retains the complete original owner. Kind and lit come from the real block state rather than stored record fields. This typed seam is ready for a block-entity storage owner; it is not an implemented NBT or durable-save codec.

The actor owns the actual block entity position, placement permissions, player stat/event context, accepted block mutation, notification delivery and spawning of item entities. The campfire owner must remain with that actor and be stepped at vanilla tick cadence. No Core, menu, player inventory, resource-frame or entry file is changed by this namespace. The integration seam is explicit rather than a sidecar world or fabricated block-entity implementation.

## Actual receiver semantics

An occupied lit slot increments progress with Java signed integer wraparound. Completion compares the incremented progress and saved total as signed ints. It selects the current recipe, preferring the still-matching cached recipe ID, before registry-order fallback. This one cached check is shared sequentially across all four slots. The cooking time stays the placement-time value even when the recipe book changes; the completion output comes from the current matching recipe. If no recipe now matches, Java drops the complete original input stack.

An enabled output is dropped and the input is cleared; progress and total are retained. A strictly invalid assembled template can produce empty output: Java still clears and notifies, and calls its drop routine even though no entity is emitted. An output disabled by current feature flags keeps the original occupied input and incremented progress for retry. A lit tick marks dirty once if any slot was occupied before processing; completed empty slots do not continue to mark dirty.

Unlit cooldown independently examines all four progress words, including empty slots. Positive signed progress uses `min(max(progress-2,0),total)` and marks dirty once for the tick. Nonpositive signed progress is unchanged. In particular a negative total can make the cooled progress negative; there is no invented range clamp.

The typed `Record` stores all four item payloads and timer words. Actual Java NBT stores `Items`, `CookingTimes` and `CookingTotalTimes`, omits the cached recipe, zeros a timer array when its field is absent, and copies only the supplied prefix when an array is present (retaining the remaining old entries). A future NBT decoder must materialize a complete `Record` using those load semantics. The reflection-based reference input loads used here exercise timer/cooking behavior, not that NBT decoder or crash recovery.

Component authority is rebuilt from the actual initialized item defaults plus the decoded patch, and the derived identity must equal the complete input key. Caller-supplied metadata or a string claiming a component envelope is not authority. Existing supported component codecs remain the admitted domain; unsupported patches and unsupported campfire recipes are explicit refusals. A feature entry absent for a due output is an authority failure, distinct from a known disabled output's successful retry transition.

## Verification and limits

`python3 tools/reference_campfire_authority.py` invokes the installed, provenance-verified 26.3 jar's unmodified `CampfireBlockEntity.placeFood`, `cookTick`, `cooldownTick`, `preRemoveSideEffects` and `clearContent`; it uses real recipe managers/cached checks, component/template codecs and normal `ItemEntity` construction. A declared reference-only `ServerLevel` fixture captures world I/O and supplies features/RNG. It does not replace cooking or recipe algorithms. The retained oracle is `reference/campfire_authority.json`; the compact receipt is `evidence/campfire-authority-reference.json`.

The oracle contains 16 scenarios and 64 action observations: both campfire kinds; four-slot placement/full refusal; unlit placement/cooldown/relighting; zero/negative/minimum cooking times; signed overflow; complete patched fallback/output; recipe replacement; disabled-result retries; cached recipe priority; strict-empty output; whole-stack and repeated removal; and absent/wrong input. All observations created zero XP entities. The full loaded input contains 1,658 initialized items, 236 tags and 116 installed recipes plus nine explicitly diagnostic recipes. Diagnostic recipes exercise general behavior and are never installed into the game catalogue by this owner.

`python3 tools/test_campfire_authority.py` checks the production owner and actual loader, emits/compiles native C and compares full effective component maps, timers, cache IDs, dirty/update/event counts and ordered aggregate item quantities with the retained Java observations. Twelve targeted guards test typed snapshot/clear/restore and noncanonical air stacks, malformed counts, forged/missing component authority, unknown items, unsupported patch/recipe domains, late-slot feature failure and invalid record loading. Java randomly splits drop stacks and chooses entity positions/velocities; the pure owner retains empty drop calls as well as occupied slots, aggregate ownership is tested here, while exact spawning, fragmentation and RNG consumption remain the real world-drop adapter's named boundary.

Fifteen implementation-connected laws live in `src/campfire_authority_laws.bend` and are ordinarily checked in `src/campfire_authority_proof.bend`. Fourteen are checked by the independent BendTT kernel using unchanged checked proof roots/types/bodies and retained original declaration maps via `tools/campfire_authority_proof.mjs`. They establish whole-owner refusal, exact placement quantity/key, creative held-input retention, disabled retry retention, enabled clearing/timer preservation, fallback stack retention, nonpositive cooldown, snapshot ownership, failed load recovery, duplicate-drop prevention, ticker cache reset and the first empty slot's placement priority. The actual signed-overflow `cook_cell` law ordinarily checks but its transitive `json.encode_go` dependency is rejected by the independent kernel's affine live-code descent check; that transition is covered by the actual Java/native observation. Broad installed `--verdict` also hit a machine-stack overflow; no toolchain or dependency source was changed to hide either limitation.

Confidence is high for the implemented transitions covered by the actual receiver, native comparisons and stated laws. Core actor adoption, NBT/durable persistence, item-entity spawning/RNG, player statistics and block/world distinctions are integration work, not claims established by these fixtures.

The accepted narrow build recorded 1.36 s/615,825,408 B sampled RSS for the ordinary receiver check, 1.12 s/241,516,544 B for the unchanged-root export, 0.22 s for the independent kernel, 10.69 s/1,729,773,568 B for C emission and 8.72 s/536,854,528 B for clang. Native execution of the whole catalogue/scenario/guard receiver took 17.73 s, with 43,909,120 B maximum resident set reported by `/usr/bin/time -l`. These are bounded verification workloads, not a world-scale block-entity performance claim. The first C attempt stopped at its 2 GiB process-tree bound before emitting C; `evidence/campfire-authority-build-failure-001.json` retains it. Shared recipe decoder dispatch repair `817231a` removed its measured long-string-pattern expansion; the changed build then passed. No unchanged recipe corpus was replayed.
