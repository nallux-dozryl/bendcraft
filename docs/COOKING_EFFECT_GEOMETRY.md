# Cooking XP placement geometry

Pinned Minecraft Java 26.3. Production lives in `cooking_effect_geometry.bend`, `cooking_effect_geometry_voxel.bend`, and `cooking_effect_geometry_world.bend`. No host gameplay, identity-placement substitute, or duplicated Core owner is used.

The entity consumer calls `place(Context, dimension, Vec3) -> Result<E.Error, Vec3>`, with `E=cooking_effect_entities_model`. The returned vector is the orb's final base position. A failure becomes `E.Refused{reason}`, allowing the existing ordered effect consumer to retain the complete failed spawn owner and suffix.

`capture(engine:G.Engine, catalog:slab_collision.Catalog, Request{dimension, coverage:AABB, environment:local_collision_world.Environment, cell_budget:Nat, voxel_budget:U32}) -> Engine & Catalog & Result<String, Context>` returns both affine owners on every path. `capture_world(W.State, catalog, request)` also preserves the client View. The existing canonical registry check, actual loaded Core reads and initialized slab catalog authorize the snapshot. A one-block read halo protects queries inside coverage; the declared clear border interior must contain `coverage.inflate(2)`, including all whole collision boxes. The current scanner admits Overworld air, stone, dirt, oak planks and all 606 actual registered slab states; unsupported states, unavailable sections, unresolved entity/border facts and exhausted budgets refuse. These are existing collision-authority bounds, not invented replacements for other block classes.

A Context is immutable query data, not an independent world authority or cached future guarantee. The Motion/actor join must supply actual entity and border admission and capture again after relevant world/collider changes. The world adapter currently accepts the existing `KnownEmptyEntityCollisions` policy only. The pure Context supports declared actual entity AABBs; it does not derive their authority. Near-border placement outside the declared clear interior remains refused. No live Core/Scene/Session, persistence or effect-entity files were edited in this lane.

The implementation preserves initial `noCollision(AABB)` with a null entity and therefore no border collision check. Obstruction triggers the actual orb search: center is base plus `(0,.25,0)`, `AABB.ofSize(center,.5,.5,.5)` is rebuilt with Java rounding order, outer query is the shape's bounds inflated by `.5`, intersecting block boxes are inflated by `.25`, unioned/optimized, and subtracted with ONLY_FIRST. Entity shapes are not subtracted during that search. The closest point follows Java's greedy box enumeration (Y, then X, then Z) and strict distance comparison, retaining the first exact tie. No free position retains the original base; a returned free center is shifted down `.25`.

The voxel implementation retains empty coordinate cells, dyadic CubePointRange merging, the 256-cell cube-merger threshold, 1e-7 indirect-merger coalescing and Java Math.round ties toward positive infinity. The production voxel budget refuses before allocating a Cartesian boolean result. Source elaboration originally expanded three overlapping U32-zero patterns beyond a 1.5 GiB Node heap; Bool predicates repair that source shape without changing semantics. No compiler changes were made.
