# Inventory number keys and offhand key

The native inventory controller requests a real `MenuClick{slot,Swap{button}}` for the hovered player-menu slot: digits 1–9 use buttons 0–8, and F/f uses button 40. The authoritative operation is the committed `player_inventory_click_swap` kernel, reached by existing private MenuClick tag 11 and correlated MenuReply tag 6. The controller owns no copied cursor stack and changes no inventory count locally.

The menu must be open, focused, uncaptured, structurally valid and idle, with an empty authoritative carried stack. An actual Move or Mouse supplies the hover coordinates. A request sets pending value 3; subsequent keys cannot issue another mutation before the correlated reply. Completion installs the complete received authority, including refusals, while retaining the pressed-key latch. Another request requires key release. The creative search tab handles text instead; a retained search tab after closing cannot swallow world number keys. Closed-menu digits and F pass through to the existing world input consumer; this change creates no world offhand operation.

Hover records the logical and drawable viewport extents that produced it. Resize or HUD-scale changes invalidate that hit before key dispatch and before drawing its highlight. Capture changes, focus loss, tab/page/search changes, opening and closing clear the relevant pointer state. Fresh pointer movement is needed to establish a hit after those transitions. Captured look deltas remain outside this coordinate mapping.

`MenuInput` and the presenter retain their existing interface. `State` has the same fields; `Hit.AtViewport` is internal coordinate provenance. The existing packet path processes actual native events through `Screen.step_frame`, serializes MenuClick, and completes only admitted epoch/sequence/framing replies. The server remains the player/menu authority. Screen does not authenticate replies itself.

Java 26.3 separates physical `key` from shortcut `keycode`: default digits 1–9 bind physical 30–38 and F binds physical 9. Modifiers do not prevent the observed requests. The native modifier-named fixtures compare that shared semantic projection and do not claim OS modifier delivery.
