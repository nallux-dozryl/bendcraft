# Pinned 26.3 player save/load reference

Confidence is **high for the recorded normal LocalPlayer receivers and exact pinned bytecode**. This is evidence preparation for future vanilla-compatible persistence. It implements no Bend save format, game state migration, player-data filesystem operation or server lifecycle. The project's existing `bendex:player-record` schema remains a separate custom raw motion/look record; these Java results do not change its contract.

`tools/reference_player_save_probe.py` constructs actual `LocalPlayer`, `Options` and `KeyboardInput`, invoking the normal actual `ClientLevel` constructor through the frozen fixture-level subclass from `tools/reference_local_input_probe.py`. The official `VanillaRegistries.createWorldLookup()` supplies the provider for actual `TagValueOutput.createWithContext`, `Entity.saveWithoutId`, `TagValueInput.create` and `Entity.load`. Output is written and reread through untouched official `NbtIo` in memory. There is no Unsafe allocation, replaced save/load method, host save algorithm, native game launch or window. Selected prior fields are seeded through official setters or reflection solely to prepare nondefault receivers.

The frozen fixture replaces four external service types: Minecraft, Gui, Tutorial and ClientPacketListener. Its level subclass supplies the declared synthetic air/stone world-query and observer services; it is not a running client world. Their complete source texts and hashes are retained alongside the new fixture and launcher under ignored `build/player-save`. The actual game implementations in the player receiver hierarchy and tag/registry codecs come from the pinned official client JAR. Every loaded official class is individually checked against that JAR. The synthetic UUID/profile and nonexistent `/dev/null/reference-local-input-fixture` options path use no account or credential data. Missing audio services are exposed as failures, not replaced with a successful gameplay implementation.

Two fresh Java processes execute the same 9 save profiles and 58 load cases. Each run saves all 9 observed receivers, completes 55 official loads and records 3 actual load errors with the receiver's post-error state. One save profile explicitly retains a partially configured FallFlying receiver after its sound notification throws. It is not counted as successful FallFlying activation. `evidence/player-save-extract.json` and `evidence/player-save-reproduce.json` separately record these outcomes; reproduction compares every full typed NBT tree, physical byte sequence, raw numeric word, receiver state and exception. Only the process-specific `TagType@hex` identity suffix inside ProblemReporter diagnostic strings is normalized. Both unmodified raw diagnostic outputs remain pinned in their full artifacts.

The reference JSON retains complete typed save roots and exact uncompressed, unnamed-root NBT bytes for every save profile. Load records retain before/after raw state and focused tag projections; their complete input/resave trees, bytes and original diagnostics remain in the hashed raw artifacts. Float and Double payloads use hexadecimal raw words. Integer arrays include signed values and raw two's-complement U32 words. The 64 KiB generated-payload ceiling and 1 MiB `NbtAccounter` are fixture resource bounds, not newly inferred vanilla admission limits. No malformed physical NBT byte corpus is claimed: tag mutations are constructed with official tag classes and pass through official NbtIo before load.

The measured core mapping is:

| Actual field | Saved key and physical type | Observed absent/load behavior |
| --- | --- | --- |
| Position XYZ | `Pos`: List of three Double tags | Missing or short list yields zero vector; load clamps X/Z to ±30,000,512 and Y to ±20,000,000. Infinite position components clamp to limits. NaN position throws after earlier mutations. |
| Delta movement XYZ | `Motion`: List of three Double tags | Missing/short list yields zero vector. Each component whose absolute value exceeds 10, including infinities and the tested NaN, becomes positive zero. Exactly ±10 survives. |
| Current yaw/pitch, degrees | `Rotation`: List of two Float tags | Missing/short list yields zero. Numeric Double list also decodes. Yaw is later reduced modulo 360; pitch uses the actual finite-check/modulo/clamp setters. Prior angles are not saved. |
| `Entity.fallDistance` | **`fall_distance`: Double** | Missing yields positive double zero. Historical `FallDistance` Float is ignored. Float/Int values coerce numerically; String is reported and defaults to zero. A Double NaN survives load after wire canonicalization. |
| Ground flag | `OnGround`: Byte | Missing yields false. Tested Byte −1, Int 2 and Float 1 yield true; Short 0 and Double NaN yield false. String `true` is reported and defaults false. |
| Health/absorption | `Health`, `AbsorptionAmount`: Float | Missing Health and tested String Health use this receiver's maximum health, 20. Other fields are retained in the exact full tree; no general equipment/effect health policy is inferred. |
| Hurt/death timers | `HurtTime`, `DeathTime`: Short | Missing yields zero. Save narrows the seeded Java ints: 65,535 → −1 and 32,768 → −32,768; load sign-extends those shorts back to ints. |
| Current impulse bookkeeping | `current_impulse_context_reset_grace_time`: Int; optional `current_explosion_impact_pos`: three-Double vector | Nondefault grace and vector roundtrip. Empty input resets grace to zero and removes the vector. |
| Sleep location | Optional `sleeping_pos`: IntArray of three coordinates | Present valid location loads the actual SLEEPING pose/dimensions. Missing or short array clears the location; the tested receiver already in SLEEPING retains that pose. |
| XP | `XpP`: Float; `XpLevel`, `XpTotal`, `XpSeed`: Int | Nondefault values roundtrip. Missing/zero XP seed invokes the actual RandomSource; the recorded fallback word is fixture-seed-specific. |
| UUID | `UUID`: IntArray of four words | Entity reads it, then Player restores its GameProfile UUID. A mutated UUID does not override this receiver's synthetic profile. |
| Abilities/food/inventory | `abilities`: Compound; four food primitives; `Inventory`, `EnderItems`: Lists | Default and selected nondefault food/XP tags are retained. Empty inventory, empty effects and default abilities do not establish populated-content coverage. |

Default save contains DataVersion Int **5023**, Pos, Motion, Rotation, fall_distance, Fire Short, Air Short, OnGround Byte, Invulnerable Byte, PortalCooldown Int, UUID, Health, HurtTime, DeathTime, AbsorptionAmount, impulse grace, attributes List, FallFlying Byte, Brain Compound, Inventory, SelectedItemSlot Int, SleepTimer Short, XP fields, Score Int, abilities, food fields and EnderItems. Optional and populated data are not inferred from this default list. The source inventory also pins conditional name/entity-data/passenger/effect/equipment/combat-memory paths, without pretending to have executed them.

Negative zero is already lost in the actual saved tag tree. The signed-zero profile supplies raw negative zeros for position, motion, current/past angles and fall distance; Pos, Motion, Rotation and fall_distance are saved as positive zero. Pinned `FloatTag.valueOf` and `DoubleTag.valueOf` compare numerically against zero and return their cached ZERO instance. The observed conversion therefore precedes NbtIo output. NbtIo also canonicalizes the deliberately supplied NaN payload when writing the floating word; pre-wire tag words and reread words are recorded separately. A future vanilla writer cannot claim this save path preserves the custom codec's signed-zero/NaN payload policy.

Load ordering matters. Nondefault source yaw 707.5 (`4430e000`) saves verbatim. Fresh load produces current yaw 347.5 (`43adc000`) but previous yaw and current head/body yaw still hold 707.5; old head/body angles retain receiver history. The requested source pitch −123.25 is already −90 (`c2b40000`) before saving because its official setter clamps it. The tested nonfinite Rotation components are rejected by those setters, retaining the seeded finite angles while load succeeds. These results must not be replaced with a single abstract "rotation normalization" step.

Runtime-only caches and derived state have a different boundary:

| Field group | Recorded serialization/load result |
| --- | --- |
| CROUCHING/SWIMMING pose, direct width/height/eye cache | No generic pose/dimension keys in these tags. Fresh receiver retains its constructor STANDING state; seeded CROUCHING receiver retains CROUCHING. Sleep location is the explicit conditional exception above. |
| Bounding box | Not saved directly. Load rebuilds from loaded position and the receiving player's existing or sleep-refreshed dimensions, replacing the seeded custom box. |
| Major collision flags and minor collision | Not saved as independent fields. Seeded horizontal/vertical/below/minor flags survive successful load; OnGround is separately overwritten. |
| Cached support position / onGroundNoBlocks | Not saved or recomputed here. Seeded `[-2,0,5]` and true survive load even when the new position changes; a fresh fixture's existing `[0,0,0]` support cache also remains. |
| Jumping, noJumpDelay, jumpTriggerTime, sprintTriggerTime | Not saved. Seeded words `ffffffff`, `80000000` and sprint counter 17 remain on a reused receiver; fresh receivers retain constructor values. |
| xxa/yya/zza, sampled keys/vector, crouching cache, bob history, stored speed | Not saved. Explicit nondefault cache values survive reused-receiver load. Device/controller semantics and a later input/tick refresh are not executed. |
| Previous look/position, current head/body look | Not separately saved. Old position and previous yaw/pitch are copied during Entity.load; current head/body yaw is assigned from loaded yaw before final modulo. Other old head/body fields retain prior values. |
| needsSync / tickCount | Load sets needsSync true; tickCount remains the seeded raw signed-int word. Neither appears as a direct tag in these saves. |

The CROUCHING and SWIMMING save profiles serialize **exactly the same complete tag tree and bytes** as the corresponding nondefault standing profile despite their different boxes, dimensions, collision/support/counter/input caches and pose. This demonstrates why a vanilla-save projection and exact next-tick replay need distinct contracts. It does not prove arbitrary states or all lifecycle paths equivalent.

Fresh save→load→save comparisons identify stable tags rather than requiring false byte equality. In every successful fresh profile, `attributes` changes: Player.readAdditionalSaveData sets movement-speed base from binary32 abilities.walkSpeed widened to double, creating base word `3fb99999a0000000`. LivingEntity reads saved attributes only when a nonnull level is **not client-side**. In this actual ClientLevel receiver, source scale 1.5 serializes but does not restore; fresh dimensions remain unscaled. Rotation additionally changes in profiles with unwrapped yaw. The reference's `roundtrips` map enumerates every unchanged top-level tag and each exact changed pair. The server-side attributes branch is pinned bytecode, not an executed normal server receiver.

Warnings are not necessarily rejection. A four-component Motion list reports a codec size error yet its partial first three components are adopted; a two-component list reports the error and defaults to zero. Non-numeric fall/ground/health values report diagnostic problems and apply the actual defaults. Injected unknown Pose/Width/Height/minor/support/jump tags are ignored. The NaN-position case throws `ReportedException` wrapping `IllegalStateException("Entity has invalid position")`; position, velocity, rotations, fall distance, ground and needsSync have already changed, while later health/counter updates have not run. Full partial state is retained. No atomic-load law is asserted.

Actual FallFlying flag notification reaches `LocalPlayer.onSyncedDataUpdated` and requests a sound from the frozen fixture's absent SoundManager. The setup setter mutates the actual flag before throwing; that exact partial receiver is saved with its configuration failure attached. Loading true FallFlying similarly reaches the same service gap and records the actual partially loaded receiver. This establishes the tag and failure path, not working flight/audio activation.

Ordinary `Player.shouldBeSaved()` returns false, so `Entity.save` returns false with an empty root in every observed profile. `saveWithoutId` is the relevant executed extraction entry. The actual PlayerDataStorage.save bytecode uses that same entry with registry context, then NbtIo.writeCompressed to a temporary `.dat` and Util.safeReplaceFile. Its load path reads compressed NBT and applies the PLAYER data fixer before returning the tag. These filesystem/data-fixer operations are **static evidence only**; no installed player save was accessed or written.

Entity, LivingEntity, Avatar, Player, ServerPlayer and the inspected shared value/tag support classes have byte-identical classfiles in the pinned client and nested server artifacts. This does not erase level-side branches or supply a normal ServerPlayer. Avatar, AbstractClientPlayer and LocalPlayer add no save/load override in this inspected chain. ServerPlayer's additional methods and helper bytecode are pinned but unexecuted: Dimension String, current/previous game-type Int writes, seenCredits/spawn_extra_particles_on_fall Boolean writes, warden tracker, recipe book, respawn, nether/explosion/raid positions, post effects, shoulder entities, root vehicle/attach and ender-pearl data. Codecs, omission conditions and direct call references are retained; complete physical types/defaults for unexecuted server codec payloads remain unverified. Dimension mutation on this LocalPlayer does not change its ClientLevel dimension.
