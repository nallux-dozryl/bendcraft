# Strict reusable UTF-8

`src/unicode.bend` implements ordinary strict UTF-8 in pure Bend. Confidence is
**high** for the stated behavior and tested native limits. It is ready for
registry and ZIP text boundaries; integration into those callers is separate
work. This module does not implement NBT's modified UTF-8.

Import the module under the `Unicode` alias:

```python
import Base
import ./unicode.bend as Unicode

# Both results, including their String errors, are reusable Data.
# The decoder limit counts output Unicode scalars.
Unicode.decode(max_scalars: Nat, bytes: List<&2, U32>)
  -> Result<&2, &2, String, String>

# The encoder limit counts output bytes.
Unicode.encode(max_bytes: Nat, text: String)
  -> Result<&2, &2, String, List<&2, U32>>
```

These are complete-input APIs. Empty input succeeds at a zero limit. A
nonempty successful decode consumes one scalar of budget per character;
encoding consumes one byte of budget per emitted byte. A limit is inclusive:
exactly the limit succeeds, one unit beyond it fails. Failure returns only an
error, never a partial String or byte list. `Decoder`, `Encoder`, and other
helpers are implementation details; callers should use `decode` and `encode`
and should not forge helper states.

The decoder rejects any list element above 255, unexpected or missing
continuations, invalid leading bytes, overlong forms, surrogate encodings,
scalars above U+10FFFF, and an incomplete final sequence. The encoder validates
each `Chr{code}` because Bend's public constructors allow a String to contain
surrogates or values above U+10FFFF. Either category fails instead of generating
malformed UTF-8.

ASCII, NUL, CR, LF, BOM and Unicode noncharacters are retained as supplied.
There is no newline handling, BOM stripping, replacement decoding, Unicode
normalization, or Unicode noncharacter filtering. NUL encodes as the single
byte `00`; the modified-UTF8 form `C0 80` is rejected. Supplementary scalars use
ordinary four-byte UTF-8, not separately encoded UTF-16 surrogate halves.

| Failure | Diagnostic |
| --- | --- |
| A byte value exceeds 255 | `input byte exceeds 255` |
| Invalid starting byte | `invalid UTF-8 leading byte` |
| Missing/invalid continuation while consuming a sequence | `expected UTF-8 continuation byte` |
| Completed overlong, surrogate, or out-of-range sequence | `invalid UTF-8 scalar or overlong encoding` |
| Input ends during a sequence | `incomplete UTF-8 sequence` |
| Decoded scalar budget exhausted | `UTF-8 scalar limit exceeded` |
| Encoded byte budget exhausted | `UTF-8 byte limit exceeded` |
| Forged invalid String character | `invalid Unicode scalar in String` |

When a payload violates several rules, callers should rely on failure rather
than on one particular precedence between diagnostics. These diagnostics are
fixed ASCII Strings; they contain no input fragments.

Native Bend 2.0.35 stores `Nat` in 48 bits, so native caller budgets must be in
`0..281474976710655` (`2^48-1`). The codec uses only matched predecessors to
consume them. It does not grow a length counter, construct a successor from a
caller limit, add lengths, narrow a Nat to U32, or subtract from zero. This
permits both a registry policy of 4,194,304 output bytes and a ZIP filename
policy of 65,535 output bytes through `encode`, with no separate hardcoded
codec ceiling. Decode limits count scalars; callers must enforce any input
byte-size policy separately before calling `decode`.

For decoder states constructed by the public API, a leading byte establishes
`need` as 1, 2, or 3 and the initial code at most 31, 15, or 4 respectively.
Each valid continuation adds at most 63 after multiplication by 64; at most
three are consumed. The
largest intermediate code is U+13FFFF, below `2^21`, so no U32 arithmetic can
overflow. The complete scalar gate rejects values above U+10FFFF. The encoder
validates the scalar before shifts and masks; every generated byte is within
0..255. These arithmetic bounds are implementation reasoning, not a claimed
universally proved parser invariant.

Verification lives in `tests/unicode.bend`, `tools/test_unicode.py`, and
`evidence/unicode-native.json`. Reproduce it from the Minecraft project root:

```sh
python3 tools/test_unicode.py
```

The script pins `/Users/chuah/.bend/bin/bend` 2.0.35, checks both Bend files with
the independent BendTT kernel, builds the native CPU executable, emits and
inspects relevant C, and runs with `--threads 1 --gpu off`. The locally cached
Lean 4.34.0 kernel dependency is added to the subprocess PATH when present.
The exact individual commands are:

```sh
/Users/chuah/.bend/bin/bend src/unicode.bend --verdict
/Users/chuah/.bend/bin/bend tests/unicode.bend --verdict
/Users/chuah/.bend/bin/bend tests/unicode.bend -o build/unicode-tests
/Users/chuah/.bend/bin/bend tests/unicode.bend -o build/unicode-tests.c
```

Both independent verdicts report `ALL PROOFS CHECK`. Six general laws prove
empty-input and single-step budget behavior. Eleven finite equalities establish
NUL, modified-NUL rejection, surrogate/out-of-range rejection, incomplete and
non-byte rejection, supplementary boundaries, and noncharacter fixtures.
Neither these laws nor the kernel verdict constitute a universal UTF-8
correctness or round-trip theorem. The implementation has no unsafe, foreign,
or axiom dependency; standard Base File/IO is used only by the native test
harness to load independently generated large fixtures.

The independent CPython strict encoder/decoder oracle covers:

- 12,125 small cases, comparing successful output values exactly and requiring
  failures to expose no partial output. This includes all single-byte values,
  all 2,048 surrogates in both directions, forged out-of-range U32 characters,
  every encoding-width boundary, all 66 noncharacters, invalid continuations,
  overlong forms, incomplete sequences and seeded random valid/malformed data.
- 33,802 input chunks, including all partitions of selected scalar encodings,
  empty chunks and multibyte splits. The harness assembles the complete input
  before decoding; these tests do not claim a streaming API.
- All 1,112,064 valid Unicode scalar values in both native encoding and decoding.
  Large outputs are checked by length and FNV-style 32-bit summaries against independent
  Python results. This is exhaustive input coverage with empirical hash checks,
  subject to hash collisions, rather than an exact proof of every large output.
- 19 large fixtures covering exhaustive scalars, 65,535-byte and 4 MiB exact and
  exceeded encoder limits, scalar decoder limits, and malformed/surrogate tails
  after long valid prefixes. Small cases also test `2^48-1` budgets.

Emitted C retains the 48-bit Nat representation, scalar and byte checks, and
zero-guarded budget predecessor operations. The compiler inlines the public
codec definitions into the harness entry paths. C inspection records selected
lines, budget excerpts and a source digest; it is not a separate proof of the C
backend. No Minecraft parity, ZIP parsing, registry installation, transport,
GPU execution, or caller integration claim is made by this evidence.

The large-output accumulator starts at 2,166,136,261, XORs each output value,
then multiplies by 16,777,619 modulo `2^32`. Encoded-byte summaries are standard
FNV-1a-32; decoded-scalar summaries XOR whole scalar numbers rather than their
octet representations. Both are calculated independently by Python and Bend.
