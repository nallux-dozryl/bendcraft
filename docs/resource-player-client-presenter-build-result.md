## Concrete next decision

Do not retry this monolith or patch the compiler based on the unsymbolized stack. The measured limitation is composition of the integrated consumer under the bounded installed route. `client_render` is proposing a real Bend actor/render split, which is a meaningful next source experiment: the accepted saved Session/native actor and resource renderer each have independent executed foundations, while all three combined layouts lack checked C under their cap.

The current source exposes coupling that its monomorphic draw change did not remove: `load_assets` retains the complete `Session.Ready` across `Render.load`; the presenter also retains the Session actor handle through render and input continuations. These are source facts, not measured compiler-cause attribution. Splitting can remove those joins without making Python implement gameplay or rendering.

The smallest credible split keeps one Bend process owning the authoritative 50ms Session actor, save lease, external TCP/MCP and unchanged 18-operation catalog. A second Bend process owns resource loading, render assets and Window/input/presentation. Its private, checked protocol must return one coherent frame sample containing tick/revision, body/look, world visibility data and palette from a single actor transaction. Independent public `player.inspect` and world queries can observe different timer ticks, so they are insufficient to establish an atomic unpaused frame. Actual Window input packets and release must enter the actor in order; render/poll requests must not advance time. A bounded request identity, size/error validation and peer failure cleanup must preserve buttons, lease and save behavior. All simulation/rendering/serialization remains Bend.

Any new split needs its own ordinary checks, sealed dependencies, bounded native build and actual resource TCP/edit/save/reload/frame regression. It has no measured build advantage yet. Reuse the independent Java idle/physics and raw saved-record/pixel expectations already prepared, preserve the failed sources/receipts, and make no claim of full-game parity or visible OS-input acceptance.
